## 1. 背景与目标

### 1.1 背景

新生儿（0-3 个月）的照护高度依赖"按需响应"：吃奶、睡觉、吃药、排便没有固定时刻表，但儿科医生和家长都需要准确的间隔数据来判断宝宝是否健康——例如"两次喂奶间隔是否超过 4 小时""今天排便几次""睡了多久"。

现状痛点：
- **靠记忆不可靠**：新手父母严重睡眠不足，凌晨喂完奶转头就忘是几点、喂了哪一侧、间隔多久。
- **纸笔/备忘录太慢**：宝宝哭闹时单手操作、夜里昏暗环境，打开备忘录翻找输入门槛太高，常常放弃记录。
- **现有 App 太重**：多数育儿 App 需要联网注册、社区、商城、推送广告，与"只想快速记一笔时间"的核心诉求相悖，且涉及隐私（婴儿健康数据上传云端）顾虑。

为什么现在做：iOS 侧「锁屏小组件（WidgetKit）+ App Intents 语音」已成熟，可真正做到"不解锁、一句话、一次点击"完成记录；Android 侧虽无锁屏小组件与第三方语音通道，但**锁屏常驻通知 action** 是稳定可用的等效路径。两端各自押注不同系统能力，都能达成"不解锁快记"。同时纯本地存储能彻底打消隐私顾虑（婴儿健康数据不上云），形成差异化。

> ⚠️ v1.0 此处曾表述为"Android App Shortcuts/Glance 已成熟"，不准确：App Shortcuts 是桌面长按快捷方式（非语音），Glance 是桌面小组件（需解锁）。v1.1 已按平台实际能力修正，详见 §3.5 / §3.6 / §3.9。

### 1.2 目标用户

| 用户角色 | 特征描述 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| 哺乳期妈妈 | 25-38 岁，产后 0-3 月，睡眠碎片化，常单手持机 | 最快记录、不费脑、夜间可操作 | 凌晨喂奶后单手记一笔；宝宝睡着后补记 |
| 新手爸爸/照护者 | 参与轮班照护，需要交接信息 | 一眼看懂"上一次是什么时候" | 接班时查看上次喂奶/排便时间 |
| 孕晚期准妈妈 | 临近生产，提前安装准备 | 简单、可预先了解 | 产前安装、产后立即使用 |
| 儿科医生（间接） | 通过家长出示记录判断健康 | 数据准确、可按天查看 | 体检时家长打开 App 展示时间轴/统计 |

## 2. 需求概述

一键记录宝宝**母乳 / 奶粉 / 睡觉 / 吃药 / 排便**五类动作，自动管理时间段的开始与打断，把一天的记录可视化为 **24 小时活动带 + 近 7 天趋势**让家长自行读出规律，纯离线本地存储。

"不解锁快记"按平台走不同路径：**iOS = 锁屏小组件 + Siri 语音**，**Android = 锁屏常驻通知 action + 桌面小组件**。

**明确不做（v1.1）**：任何健康状态判断、阈值提醒、主动推送；任何数据上云与多设备同步。

## 3. 功能详细设计

### 3.0 事件模型总览（核心概念）

App 处理两类事件，这是所有功能的基础。**注意「吃奶」在 v1.1 拆分为母乳与奶粉两种记录形态**：

| 事件类型 | 事件 | 形态 | 记录内容 | 是否会被打断 | 提交方式 |
|---------|------|------|---------|------------|---------|
| 时间段事件（Interval） | 吃奶 · **母乳** | 开始时刻 + 结束时刻 | 时长 + 左右侧（可选） | 是 | 两次点击（开始 / 结束） |
| 时间段事件（Interval） | 吃奶 · **奶粉** | **零时长段**（开始 == 结束） | **毫升数**（必填） | 是 | **一次点击 + 选毫升** |
| 时间段事件（Interval） | 睡觉 | 开始时刻 + 结束时刻 | 时长 | 是 | 两次点击 |
| 瞬时事件（Instant） | 吃药 | 单一时刻 | — | 否（不打断时间段，独立记录） | 一次点击 |
| 瞬时事件（Instant） | 排便 | 单一时刻 | — | 否（不打断时间段，独立记录） | 一次点击 |

**核心打断规则（状态机）**：同一时刻最多只有一个"进行中"的时间段事件。
- 提交一个新的**时间段事件**（母乳/睡觉）时：若当前已有进行中的时间段事件，则把它的结束时刻设为"现在"，再将新事件标记为进行中（开始时刻=现在）。
- 提交一个**瞬时事件**（吃药/排便）时：仅在该时刻新增一条瞬时记录，**不影响**当前进行中的时间段事件（睡觉可以在吃药/排便的同时继续）。
- 提交**奶粉**时：走独立入口 `submitFormula`，打断当前进行中的时间段事件（结束于"现在"），并写入一条 `开始 == 结束 == 现在` 的零时长段。**奶粉永不处于"进行中"状态。**

> **设计取舍说明 1（瞬时不打断）**：现实中"吃药/排便"发生时宝宝可能仍在睡觉，因此瞬时事件不强制打断睡觉；这样更符合真实照护语义，也避免误把睡眠切碎。（需求来源：业务判断 + 用户场景）

> **设计取舍说明 2（为什么奶粉不是瞬时事件）**：奶粉的本质是"某时刻喝了 N 毫升"，看起来该建模为瞬时事件。但这样会撞上取舍 1——宝宝被抱起来喂奶粉时，睡眠段**确实被打断了**，若按瞬时处理则睡眠段不会结束，数据失真。
> 建模为「零时长时间段」后：打断语义天然正确，且状态机主流程与 v1.0 既有测试用例完全不需要改动。代价是时间轴上奶粉显示为一个点而非区间条（可接受，视觉上用「奶瓶图标 + 毫升数」标注）。

**事件属性字段**：

| 字段 | 适用事件 | 必填 | 取值 |
|------|---------|------|------|
| `volume_ml` | 吃奶 · 奶粉 | **是** | 正整数毫升。UI 提供快选档位 30 / 60 / 90 / 120 / 150 + 自定义输入 |
| `breast_side` | 吃奶 · 母乳 | 否 | 左 / 右 / 双侧。结束喂养时可一次点选，可跳过，也可事后在时间轴编辑 |

### 3.1 一键快速记录（首页大按钮）

**功能描述**：首页提供五个大圆角按钮（**母乳 / 奶粉** / 睡觉 / 吃药 / 排便），点一下即以"当前时刻"完成记录。
**用户故事**：作为哺乳期妈妈，我希望点一个大按钮就记好，以便宝宝哭闹时单手也能完成。
**优先级**：P0

**业务规则**：
1. 点击**"母乳"**：触发时间段打断状态机（见 3.0）。若母乳已是进行中状态，再次点击视为"结束当前段"，将其结束时刻设为现在。
2. 点击**"奶粉"**：弹出**毫升快选面板**（底部半屏，非模态阻断），提供 30 / 60 / 90 / 120 / 150 ml 五个档位 + 自定义数字输入。选定即调用 `submitFormula`，写入一条零时长记录并打断当前进行中段。**面板不选中不写库**（可下滑或点空白关闭，等同取消）。
3. 点击**"睡觉"**：同规则 1。
4. 点击**"吃药"**或**"排便"**：新增一条瞬时记录，时刻=现在，不打断任何进行中段。
5. 母乳结束时，可选一次点选**左 / 右 / 双侧**（`breast_side`）。该步骤**可跳过**，跳过后字段为空，不影响记录已落库；可事后在时间轴补填。
6. 每次记录后，首页"当前状态卡"实时更新：显示正在进行的时间段事件及其已持续时长（实时走秒），以及最近一次各事件的相对时间（如"母乳 12 分钟前"、"奶粉 60ml · 2 小时前"）。
7. 记录成功后给予轻量触觉/视觉反馈（按钮高亮 + 状态卡刷新），无需弹窗确认。
8. 默认记录时刻为"现在"；用户可在记录后于时间轴中手动修正时刻与毫升数（见 3.3）。

**交互流程**：

*母乳（两次点击）*
1. 点"母乳" → 状态卡切换为"母乳进行中 00:00:xx"，按钮变为高亮的"结束喂养"态。
2. 喂完再点"母乳" → 段结束，弹出左右侧一行三选（可跳过）→ 状态卡刷新。

*奶粉（一次点击）*
1. 点"奶粉" → 底部升起毫升快选面板（默认焦点落在上次使用的档位）。
2. 点档位（如 90）→ 立即写库、面板收起、状态卡显示"奶粉 90ml · 刚刚"。
3. 目标时长 < 2 秒（含面板升起）。

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 本地存储写入失败 | 重试一次，仍失败则缓存待写入（含 volume_ml） | "记录未保存，请重试" |
| 系统时间被手动改动导致时刻倒挂 | 拒绝写入早于"进行中事件开始时刻"的结束时间 | "时间异常，请检查系统时间" |
| 毫升数为 0 / 负数 / 非数字 | 阻止写库，保持面板打开 | "请输入有效的毫升数" |
| 毫升数超出合理区间（> 500ml） | 允许写入但二次确认 | "确认一次喝了 500ml 以上？" |
| 奶粉面板打开时来了电话/切后台 | 面板状态保留，回到前台仍可继续选择 | — |

### 3.2 当前状态卡（实时计时）

**功能描述**：首页顶部展示当前进行中的时间段事件、已持续时长（走秒）、以及各事件"距上次"的相对时间。
**用户故事**：作为夜班照护者，我希望一眼看到"宝宝已经睡了多久、距上次喂奶多久"，以便判断是否该喂奶。
**优先级**：P0

**业务规则**：
1. 有进行中事件时，显示其类型、开始时刻、已持续时长（hh:mm:ss 实时刷新）。
2. 无进行中事件时，显示"当前无进行中的活动"。
3. 五项分别显示"距上次"相对时间：**母乳 / 奶粉 / 睡觉 / 吃药 / 排便**。瞬时事件取最近一条记录时刻，时间段事件取最近一段的开始时刻（奶粉取该零时长段的时刻）。
4. 相对时间随时间自动刷新（如"12 分钟前"→"13 分钟前"）。
5. **额外突出"距上次喂奶"**：取母乳与奶粉中**更近的一次**，并标注类型与毫升数（如"喂奶 · 42 分钟前 · 奶粉 90ml"或"喂奶 · 12 分钟前 · 母乳"）。这是家长判断喂养间隔最常用的单一信息，字号/权重高于其余四项。
   - ⚠️ 该项仅陈述客观事实（距今多久、上次是什么），**不得**附加"该喂奶了""间隔过长"等判断性文案（见 §3.4 范围边界与 §4 合规要求）。
6. 奶粉记录的展示带毫升数（如"奶粉 60ml · 2 小时前"），母乳带时长（如"母乳 18 分钟 · 2 小时前"）。

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 进行中事件开始时刻晚于当前系统时间 | 视为数据异常，标记需修正 | "时间异常，请在时间轴修正" |

### 3.3 时间轴与记录管理

**功能描述**：按天展示所有事件记录（时间段显示为区间条，瞬时显示为时间点），支持编辑时刻、删除、补记。
**用户故事**：作为家长，我希望回看今天/昨天的完整记录并能修正记错的时间，以便数据准确给医生看。
**优先级**：P0（查看/编辑）/ P1（补记历史）

**业务规则**：
1. 默认按"今天"展示，可左右切换日期或日历选择。
2. 时间段事件显示开始-结束区间与时长；进行中的段显示"进行中"。
3. 编辑：可修改任一记录的开始/结束/发生时刻，以及 `volume_ml`（奶粉）、`breast_side`（母乳）、类型与备注；修改时间段结束时刻时，若与下一段冲突，按时间先后自动校验（结束不得早于开始）。
   - **奶粉（零时长段）编辑时刻时，`start_at` 与 `end_at` 必须同步移动**，以保持 `start == end`（不变量 I4）。UI 上只暴露一个时刻选择器，不分别显示开始/结束。
   - 修改 `volume_ml` 走 §3.1 同一校验规则（正整数，> 500 需二次确认）。
4. 删除：删除单条记录，需二次确认；删除进行中的时间段事件后，状态回到"无进行中"。
5. 补记：可手动添加过去某时刻的记录，遵守同样的打断状态机（按时刻插入并重算受影响区间）。

**交互流程**：
1. 用户从底部 Tab 进入"时间轴"。
2. 选择日期，浏览记录。
3. 点击某条记录 → 编辑面板（修改时刻/类型/备注/删除）。
4. 成功：列表即时刷新。

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 修改后时间区间非法（结束早于开始） | 阻止保存 | "结束时间不能早于开始时间" |
| 当天无任何记录 | 显示空状态引导 | "今天还没有记录，点首页按钮开始" |

### 3.4 活动曲线与统计

**功能描述**：把一天的记录可视化为「活动曲线」，让家长自己看出宝宝的作息规律与变化趋势。分三层呈现。
**用户故事**：作为妈妈，我希望一眼看出宝宝今天白天睡得很碎、晚上有没有整觉、奶量比昨天多了还是少了，以便心里有数，也能在体检时直接给医生看。
**优先级**：24h 活动带 **P0** ／ 近 7 天趋势 P1 ／ 数字汇总 P1

> **为什么 24h 活动带从 v1.0 的 P1 提到 P0**：这是本产品区别于「备忘录 + 计时器」的唯一理由。用户描述的核心逻辑是"记录宝宝一天的活动曲线，根据统计发现宝宝状态信息"——若只有数字汇总，产品价值停留在记录工具，留存动机不足。

#### 3.4.1 24 小时活动带（P0）

**形态**：横轴为 0:00–24:00 的一天，纵向四条并行泳道（喂养 / 睡觉 / 吃药 / 排便）。
- 时间段事件画成**横向色条**（长度=时长），进行中的段画到"现在"并以呼吸/斜纹端点表示未结束。
- 瞬时事件画成**圆点**，落在对应时刻。
- **奶粉**为零时长段，画成泳道上的**奶瓶标记点 + 毫升数气泡**，不画色条。
- **母乳**色条上可叠加左右侧标识（若已填）。

**业务规则**：
1. 默认显示"今天"，可左右滑动或日历切换日期；支持连续多天纵向堆叠对比（最多 7 天同屏）。
2. 当前时刻画一条竖直"现在线"，仅在查看今天时显示。
3. 泳道高度固定，色条按时间比例映射；小于 3 分钟的段有最小可见宽度（避免看不见）。
4. 点击任一色条/标记点 → 跳转时间轴对应记录（可编辑）。
5. 夜间时段（默认 22:00–06:00，可在设置中调整）背景做浅色区分，帮助识别昼夜节律。

#### 3.4.2 近 7 天趋势（P1）

**形态**：按天聚合的折线/柱状图，可切换指标。

| 指标 | 口径 | 备注 |
|------|------|------|
| 每日总奶量 (ml) | 仅 `FORMULA` 段 `volume_ml` 求和 | **母乳不计入**，见下方口径约束 |
| 每日喂奶次数 | FEED 记录条数 | 可拆分母乳/奶粉两条线 |
| 每日睡眠总时长 | SLEEP 段按 `splitByDay` 拆分累计 | — |
| 每日睡眠段数 | SLEEP 段计数 | 反映睡眠碎片化程度 |
| 每日排便 / 吃药次数 | INSTANT 记录计数 | — |

#### 3.4.3 数字汇总（P1）

今日 / 近 7 天可切换：喂奶次数与累计时长、睡眠累计时长 + 段数 + 最长一段、排便次数、吃药次数、奶粉总毫升。
- 进行中的时间段事件按"开始时刻至今"计入当日已发生时长（实时）。
- 跨天的时间段事件按时长归属到各自然日拆分计入（如 23:00 睡到次日 02:00，分别计入两天）。

#### ⚠️ 奶量口径约束（必须遵守）

混合喂养时，「24h 总奶量」**只包含奶粉，是不完整数据**。任何呈现该数字的界面都必须：
1. 显式标注口径，如「奶粉量 480ml（母乳 3 次未计入）」；
2. **禁止**使用"总摄入量""奶量不足""达标"等表述；
3. 在母乳次数 > 0 时，同屏展示母乳次数/时长，避免家长误判宝宝摄入不足而过度喂养。

#### 🚫 范围边界：本版本不做洞察提示与主动推送（已决策）

v1.1 **明确不包含**以下能力：
- 规则化状态提示（如"距上次喂奶已超 3.5 小时""今日奶量偏低""睡眠碎片化"）
- 月龄参考区间对照
- 任何形式的主动通知 / 推送 / 提醒

**决策理由**：
1. **合规风险**：对婴儿健康数据给出"状态判断"会使产品从「记录工具」滑向「健康建议/辅助诊断」，触发 App Store 审核指南 1.4.1（医疗类 App 需资质）与国内医疗器械软件（SaMD）边界认定。措辞稍有不慎即可能卡上架或被要求资质。
2. **责任风险**：新生儿喂养间隔的"正常值"随月龄、体重、医嘱差异极大，内置阈值一旦误导家长，后果严重且不可控。
3. **产品定位**：核心价值是"把数据清晰呈现，让家长自己看出规律"，而非"App 替家长下判断"。可视化做得足够好，家长自然能读出信息。

> 若后续版本要加，必须先过合规评审，并以"家长自定义提醒"（用户自己设阈值，App 不背书数值）而非"App 推荐阈值"的形态实现。**Android 端的常驻通知（§3.9）不在此列**——它是记录入口，不承载任何状态判断或提醒文案。

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 数据为空 | 活动带显示空泳道 + 现在线；趋势图显示零值占位 | "暂无数据" |
| 当天记录数极多（> 100 条） | 活动带正常渲染，瞬时点重叠时做视觉聚合 | — |
| 跨天段在单天视图 | 只画落在当天的部分，端点标注"承接昨日/延续明日" | — |

### 3.5 小组件一键记录（**双端能力不对称**）

**功能描述**：提供小组件，无需进入 App 即可点按记录事件并显示当前状态。
**用户故事**：作为妈妈，我希望不解锁手机点一下就能记录，以便夜里最快完成。
**优先级**：iOS 锁屏小组件 **P0** ／ Android 桌面小组件 P1

> ⚠️ **平台现实（v1.0 此处有误，已修正）**：v1.0 写的是"在**锁屏**和桌面提供小组件"，双端统一。**Android 自 5.0 起已移除锁屏小组件能力**，第三方 App 无法在 Android 锁屏放置可点击组件。因此：
> - **iOS**：锁屏小组件是"不解锁记录"的主路径 → **P0**
> - **Android**：桌面小组件需先解锁到桌面，**不构成"不解锁"路径** → 降为 P1；Android 的"不解锁记录"由 §3.9 常驻通知承担（P0）

**业务规则**：
1. 小组件提供快捷记录入口（母乳 / 奶粉 / 睡觉 / 吃药 / 排便），点击直接以"现在"写入并触发同一状态机。
2. **奶粉在小组件上的处理**：小组件无法承载毫升选择面板，因此中尺寸小组件直接内联 **3 个常用毫升档位按钮**（默认 60 / 90 / 120，可在 App 设置中改为任意三档），点一下即以该毫升数写入。小尺寸小组件不含奶粉入口。
3. 小组件展示当前进行中事件与已持续时长（受系统刷新频率限制，可能非每秒刷新）。
4. 小组件写入与 App 内写入共享同一本地数据源，保证一致。
5. 规格：小尺寸（仅状态 + 单按钮）／ 中尺寸（多按钮 + 状态 + 奶粉三档）。
6. iOS 锁屏小组件额外提供圆形/矩形/行内三种形态，行内形态显示"距上次喂奶 xx 分钟"。

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 系统限制后台写入 | 写入主 App 共享容器，下次打开同步刷新 | 小组件短暂显示"处理中" |
| **iOS 锁屏状态下写入被文件保护拦截** | App Group 容器内 DB 文件保护等级必须为 `NSFileProtectionCompleteUntilFirstUserAuthentication`，**不得**设为 `NSFileProtectionComplete`（否则锁屏后不可写，记录静默丢失） | — |
| Android 12+ 小组件圆角/点击区被系统裁剪 | 遵循 Glance 规范预留边距，点击区不小于 48dp | — |

### 3.6 系统语音记录（**仅 iOS**）

**功能描述**：通过 iOS Siri / App Intents 用一句话完成记录，无需解锁打开 App。
**用户故事**：作为抱着宝宝的家长，我希望说一句话就记录，以便双手不空时也能记。
**优先级**：P1（iOS 专属）

> ⚠️ **平台现实（v1.0 此处有误，已修正）**：v1.0 把 Android 语音方案写为"App Shortcuts（shortcuts.xml，含 voice 触发）"。**该前提不成立**：
> 1. App Shortcuts 是**桌面长按图标弹出的快捷方式**，不具备任何自定义语音短语触发能力；
> 2. Google 的 **Conversational Actions（第三方自定义语音动作）已于 2023-06-13 正式关停**，官方未给第三方 App 保留自定义语音短语通道；
> 3. App Actions 的 Built-in Intents 中**没有**婴幼儿喂养/睡眠记录对应的意图类型。
>
> 结论：**Android 端 MVP 不做语音记录**，"不解锁记录"改由 §3.9 常驻通知承担。后续可评估 `androidx.appfunctions`（AppFunctions，接入 Android 智能体系统 / Gemini）作为 V1.2 探索项，但需先核实 minSdk、地区与厂商可用范围，**不得进入 MVP 关键路径**。

**业务规则（iOS）**：
1. 为五类记录动作各提供一个 App Intent：`记录宝宝睡觉` / `结束睡觉` / `记录宝宝吃母乳` / `结束吃母乳` / `记录宝宝喝奶粉 N 毫升` / `记录宝宝吃药` / `记录宝宝排便`。
2. **奶粉语音必须支持参数**：通过 Siri 参数对话获取毫升数（"喝了多少毫升？"→"90"）。若用户一句话已带数值（"宝宝喝了 90 毫升奶粉"）则直接解析，不再追问。
3. Intent 触发后等同点击对应按钮，遵守同一状态机与 `submitFormula`。
4. 使用系统自带语音能力，App 自身**不录音、不做语音识别、不联网**。
5. Intent 设置 `openAppWhenRun = false`，保证锁屏后台执行不跳转 UI。
6. 用户可在系统"快捷指令"App 中自定义触发短语。
7. iOS 16 需用户手动添加到 Siri；iOS 17+ 通过 App Shortcuts 自动暴露短语，无需手动配置。**首次启动时检测并提供一次性引导**。

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| Siri 未开启 / 锁屏禁用 Siri | 引导前往系统设置 | "请在设置 > Siri 中允许锁屏时使用" |
| 语音未识别到毫升数且对话超时 | 放弃写入，不产生半条记录 | "没有听清毫升数，已取消" |
| 解析出的毫升数非法（0/负数/超大） | 走 §3.1 同一校验规则 | 同 §3.1 |
| 设备/系统不支持（iOS 16 以下） | 隐藏语音项，降级为小组件入口 | — |

### 3.7 多宝宝档案（V1.1，非 MVP）

**功能描述**：支持记录多个宝宝（如双胞胎），各自独立时间轴与统计。
**优先级**：P2（后续版本，MVP 不含，但数据模型预留 babyId 字段）

### 3.8 设置

**功能描述**：宝宝昵称/生日、夜间模式、数据导出（本地文件）、关于与隐私说明。
**优先级**：P1

**业务规则**：
1. 数据导出：将本地记录导出为设备本地文件（如 CSV/JSON），通过系统分享面板由用户自行处理，App 不主动上传。导出字段含 `feed_method` / `volume_ml` / `breast_side`。
2. 隐私说明：明确"所有数据仅存于本机，App 不发起任何业务网络请求"。
3. 夜间模式：暗色暖调主题，降低夜间刺眼。
4. **小组件/通知的奶粉快捷档位**：可自定义 3 个毫升档位（默认 60 / 90 / 120）。
5. **Android 常驻通知开关**：默认开启，可关闭；关闭后仅保留桌面小组件与 App 内记录。
6. 夜间时段定义（默认 22:00–06:00），供活动带昼夜背景区分使用。

### 3.9 Android 锁屏常驻通知一键记录（**Android P0，新增**）

**功能描述**：在 Android 通知栏常驻一条通知，携带事件 action 按钮，**锁屏状态下无需解锁即可点击完成记录**。
**用户故事**：作为夜里喂奶的 Android 妈妈，我希望亮屏就能在锁屏上点一下记好，不用解锁、不用找 App 图标。
**优先级**：**P0（Android 端）**

> **为什么这是 P0**：Android 没有锁屏小组件（§3.5）、没有第三方自定义语音通道（§3.6）。**常驻通知是 Android 端实现"不解锁一键记录"这一核心差异化的唯一可靠路径。** 不做这条，产品在 Android 上就退化成一个普通记录 App。

**业务规则**：
1. 通知为 `ongoing` 常驻通知，**低优先级、静音、无震动、不发出任何声音**——它是记录入口，不是提醒（见 §3.4 范围边界）。
2. 通知内容分两行：
   - 标题行：当前进行中事件 + 已持续时长（如"睡觉中 · 01:23:45"），无进行中事件时显示"宝宝记录"。
   - 副标题行：距上次喂奶相对时间（如"上次母乳 · 42 分钟前"）。
3. **action 按钮**：受系统限制（折叠态最多 3 个可见），采用如下设计：
   - 展开态提供 5 个 action：`母乳` / `奶粉` / `睡觉` / `吃药` / `排便`
   - 折叠态优先展示 `母乳` / `睡觉` / `奶粉`（按使用频率排序，可在设置中调整）
4. **进行中事件的 action 动态变化**：若睡觉进行中，`睡觉` action 文案变为 `结束睡觉`；母乳同理。
5. **奶粉毫升**：通知 action 无法弹出选择面板。点击 `奶粉` action 后：
   - 默认以**上次使用的毫升数**直接写入，并在通知上显示可撤销提示（"已记录 90ml · 撤销"，5 秒内可点撤销）；
   - 若从未记录过奶粉（无历史档位），则唤起 App 的毫升快选面板（此时需解锁，属可接受降级）。
6. 通知 action 点击后：写入 Room → 刷新通知内容 → 触发 Glance 小组件更新。全过程不打开 App UI。
7. action **不得**设置 `setAuthenticationRequired(true)`，否则锁屏点击会强制解锁，功能失效。

**权限与保活**：
| 项 | 要求 |
|---|------|
| `POST_NOTIFICATIONS` | Android 13 (API 33)+ 运行时申请。首次启动时以"锁屏一键记录需要通知权限"为文案申请，说明用途，不使用诱导话术 |
| 前台服务 | Android 14 (API 34)+ 用户可手动划掉普通 ongoing 通知，需 `foregroundService`（type 建议 `specialUse`，并在 Play 上架时提交用途说明）保证常驻 |
| 电池优化 | 部分国产 ROM（MIUI/EMUI/ColorOS）会激进杀后台。首次设置时提供"自启动/后台运行"引导页，按厂商分支给出图文步骤 |
| 用户拒绝通知权限 | 降级：隐藏通知入口，保留桌面小组件 + App 内记录；设置页保留可重新开启的入口与说明 |

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 用户拒绝通知权限 | 降级为桌面小组件 + App 内记录 | "开启通知后可在锁屏直接记录" |
| 通知被用户手动划掉 | 前台服务在 5 秒后重建通知（不无限高频重试） | — |
| ROM 杀后台导致通知消失 | App 下次启动时检测并重建；设置页提供厂商保活引导 | — |
| action 点击后写库失败 | 通知显示失败态，不静默丢弃 | "记录未保存，点击重试" |
| 撤销窗口内用户又点了一次 | 撤销仅回滚最近一条，新记录独立保留 | — |

## 5. 数据需求（本地埋点，仅设备内统计，不上传）

| 事件名 | 触发条件 | 关键属性 | 用途 |
|--------|---------|---------|------|
| record_created | 任一记录写入成功 | type, **feed_method(BREAST/FORMULA)**、**volume_ml**、**breast_side**, source(APP/WIDGET/VOICE/NOTIFICATION), timestamp | 统计日均记录次数与入口占比；母乳/奶粉配比 |
| interval_interrupted | 时间段事件被打断 | from_type, to_type, duration_ms | 验证打断状态机使用 |

| record_edited | 编辑某条记录 | type, field_changed（含 volume_ml / breast_side） | 评估记录准确度；毫升数记错率 |
| day_viewed | 打开统计/时间轴某天 | date | 使用频次 |

> 所有埋点仅在设备本地计算与展示，不上传。`notification_used` 占比是 Android 端是否达成"不解锁记录"目标的**唯一可验证指标**，对应 §1.3 的"快捷入口有效 ≥ 30%"。

## 6. 验收标准（Given-When-Then）

| 编号 | 场景 | Given（前提） | When（操作） | Then（预期结果） |
|------|------|-------------|-------------|-----------------|
| AC-1 | 开始睡觉 | 无进行中事件 | 点"睡觉" | 新增进行中睡觉段，开始时刻=现在，状态卡走秒 |
| AC-2 | 睡觉被吃奶打断 | 睡觉进行中 | 点"母乳" | 睡觉段结束时刻=现在，新增进行中母乳段 |
| AC-3 | 瞬时不打断时间段 | 睡觉进行中 | 点"排便" | 新增排便瞬时记录，睡觉段仍进行中、结束时刻不变 |
| AC-4 | 结束当前段 | 母乳进行中 | 再次点"母乳" | 母乳段结束时刻=现在，状态变为无进行中 |
| AC-5 | 状态卡计时 | 睡觉进行中已 5 分钟 | 停留首页 | 已持续时长每秒刷新，显示约 00:05:xx |
| AC-6 | 时间轴查看 | 今天有≥1条记录 | 进入时间轴 | 按时间顺序显示，时间段显示区间与时长，奶粉显示时刻+毫升 |
| AC-7 | 编辑时刻 | 存在一条睡觉记录 | 修改结束时刻早于开始 | 阻止保存并提示非法 |
| AC-8 | 统计准确 | 今日母乳3次共45分钟、奶粉2次共150ml | 打开统计今日 | 显示喂奶次数=5、母乳总时长=45分钟、奶粉总量=150ml |
| AC-9 | 小组件记录 | 小组件可见 | 点小组件"吃药" | 新增吃药瞬时记录，App 内时间轴同步可见 |
| AC-10 | 语音记录（**仅 iOS**） | 已配置 App Intent | 对 Siri 说"记录宝宝睡觉" | 等同点"睡觉"，触发状态机，App 不被打开 |
| AC-11 | 离线零请求 | 飞行模式 | 完成所有核心操作 | 全部成功，无任何业务网络请求 |
| AC-12 | 跨天统计 | 睡觉 23:00→次日 02:00 | 查看两日统计 | 1 小时计入前一天，2 小时计入后一天 |
| **AC-13** | **奶粉一次性提交** | 无进行中事件 | 点"奶粉"→选 90 | 新增 FEED 记录：feed_method=FORMULA、start==end==现在、volume_ml=90、ongoing=false |
| **AC-14** | **奶粉打断睡眠** | 睡觉进行中 | 点"奶粉"→选 60 | 睡觉段结束时刻=现在；新增 FORMULA 零时长段 volume_ml=60；无 ongoing |
| **AC-15** | **奶粉连续两次** | 已有一条 FORMULA 记录 | 再次点"奶粉"→选 120 | 产生第 2 条独立 FORMULA 记录，不覆盖、不合并；无 ongoing |
| **AC-16** | **毫升数校验** | 奶粉面板打开 | 输入 0 / 负数 / 空 | 阻止写库，面板保持打开，提示"请输入有效的毫升数" |
| **AC-17** | **24h 活动带渲染** | 今日有母乳段、睡眠段、奶粉点、排便点各≥1 | 打开活动带 | 四泳道正确呈现：时间段为色条、奶粉为奶瓶标记+毫升气泡、排便为圆点；"现在线"位置正确 |
| **AC-18** | **奶量口径标注** | 今日既有母乳又有奶粉 | 查看总奶量 | 显示"奶粉量 XXXml"并标注"母乳 N 次未计入"；界面无"总摄入/不足/达标"等表述 |
| **AC-19** | **Android 锁屏通知记录** | Android 已授予通知权限、通知常驻、设备锁定 | 亮屏后点通知"排便" action | **无需解锁**即写入成功，通知副标题刷新，App 内时间轴同步可见，source=NOTIFICATION |
| **AC-20** | **Android 通知权限降级** | 用户拒绝通知权限 | 使用 App | 不崩溃、不反复弹窗；桌面小组件与 App 内记录全部可用；设置页可重新开启 |
| **AC-21** | **iOS 锁屏写入** | iOS 设备已锁定（开机后曾解锁过） | 通过锁屏小组件或 Siri 记录 | 写入成功，无静默丢失；DB 文件保护等级为 CompleteUntilFirstUserAuthentication |

### 7.3 建议实施顺序

1. **先做数据模型迁移**（`feed_method` / `volume_ml`）——这是所有后续工作的地基，且涉及已有数据，越晚做迁移成本越高。
2. 再做 **Android 常驻通知**——Android 端核心差异化，目前是 0，且与数据模型改动解耦，可并行。
3. 然后 **奶粉快选面板 + submitFormula**——依赖步骤 1。
4. 最后 **24h 活动带 + 趋势图**——工作量最大，但依赖前三步的数据完整性。
5. 文案合规审查与真机锁屏实测放在发布前，不可跳过。
